Sensor placement: data wrangling using DSL allocation layer

Author

Dusty Gannon

Published

September 18, 2026

This document prepares the inputs used by sensor_placement.qmd and the optimization scripts (python/sensor_site_optim.py, python/biodiv_site_optim.py): it starts from an allocations layer (ESRF_Allocations_20260825.gpkg) sent by Kaitlyn Athearn on 25 August 2026, builds a grid of candidate sensor locations with their environmental covariates, and computes distance to the nearest road. This document must be rendered before sensor_placement.qmd, since the latter reads the files written here rather than re-deriving them.

1 Loading the raw data

I start from the ESRF_Allocations_20260825 layer stored in ESRF_Allocations_20260825.gpkg provided by K. Athearn and use the stand and watershed attributes therein.

Important

The most up-to-date allocation information is in the ops_allocation field of this layer and not the hcp_allocation field, which reflects historical allocations. This version of the document uses the ops_allocation field.

Code 
import pandas as pd
import numpy as np
import geopandas as gpd
from skimpy import clean_columns
from pyprojroot.here import here

f = here('Data/esrf_alloc/ESRF_Allocations_20260825.gpkg')
bio_f = here(
    'Data/esrf_alloc/biodiv_sites/'
    'ESRF 2023 Biodiversity Surveys_AdjustedSiteCentersInverts.shp'
)
roads_f = here('Data/esrf_alloc/ESRF_roads_ODF.gpkg')

# load data
esrf = gpd.read_file(f, layer='ESRF_Allocations_20260825')
bio_sites = gpd.read_file(bio_f)
roads = gpd.read_file(roads_f)

esrf = clean_columns(esrf)
bio_sites = clean_columns(bio_sites)
roads = clean_columns(roads)

# convert ops_allocation values to snake_case 
esrf['ops_allocation'] = (
    esrf['ops_allocation']
    .str.replace(r'[^0-9a-zA-Z]+', '_', regex=True)
    .str.lower()
)

# convert hcp allocation to snake case
esrf['hcp_allocation'] = (
    esrf['hcp_allocation']
    .str.replace(r'[^0-9a-zA-Z]+', '_', regex=True)
    .str.lower()
)

# convert treatments to snake case
esrf['hcp_ws_assignment'] = (
    esrf['hcp_ws_assignment']
    .str.replace(r'[^0-9a-zA-Z]+', '_', regex=True)
    .str.lower()
)

# remove riparian buffers from consideration
esrf = esrf.loc[
    ~esrf['ops_allocation'].str.contains(r'_rca', regex=False),
    :
]
Important

Note that the CBMA-CRW polygons include what was allocated as RCA. I am not sure if this was by design or if the RCA polygons need to be clipped from the CBMA-CRW polygons.

2 Computing proportion of each watershed allocated to the triad levels

The new allocation layer does not designate triad treatments to watersheds. With the changes to allocations, watersheds that were assigned to triad treatments, particularly those assigned to the Triad-E treatment, have much different proportions of each stand treatment type (Reserve, Extensive, or Intensive) now. Table 2 lists the changes made to each watershed while Figure 2 shows how the watersheds fall in the ternary plot, colored by their original triad assignments.

The important take-aways from Table 2 and Figure 2 are that the Triad-E watersheds have been pushed towards higher proportions of reserve than the original design. This indicates that a regression-type approach, using mixture models may be better than considering the watersheds as belonging to the original treatment designations. I therefore use the proportions of area allocated to each stand treatment type to redesignate the watershed treatments. For example, watershed 26 must be reassigned from Triad-E to CRW (reserve).

Important

I use the watershed treatment types (CRW reserve, Intensive, Triad-I, Triad-E, and Extensive) as a starting point to ensure the initial placement of sensors spans a good range of the triad experiment, but use a regression approach with continuous measures of proportions of each watershed type in defining the objective function for the optimization scheme. The watershed treatment assignments below are therefore just a construct to aid in visualization and initialization.

To reassign watersheds to original treatment constructs, I define a band around the Cox direction for the Extensive treatment Figure 3. Treatments are then designated by the proportion of Extensive, with less than 5% as Intensive, between 5% and 40% as Triad-I, between 40% and 80% as Triad-E, and more than 80% as Extensive. Those with more than 95% reserve are designated as control/reserve watersheds. Watersheds falling outside the band around the Cox direction are left unassigned but elligible for sensor placement (colored purple in Figure 3).

Code 
# redesignate the watersheds based on where they fall in the ternary
# plot above. Watersheds with no original assignment, or assigned
# crw_partial, keep their original hcp_ws_assignment value. A watershed
# is only assigned one of the triad classes if it falls within a band
# around the reserve == intensive diagonal; its sub-class is then
# determined by prop_extensive. This mirrors classify_triad() below,
# used to trace the same boundaries over the full simplex.
eligible = (
    triad['hcp_ws_assignment'].notna()
    & (triad['hcp_ws_assignment'] != 'crw_partial')
)
in_band = (triad['prop_reserve'] - triad['prop_intensive']).abs() <= 0.2

triad['triad_trt2'] = np.select(
    condlist=[
        eligible & (triad['prop_reserve'] > 0.95),
        eligible & in_band & (triad['prop_extensive'] < 0.05),
        eligible & in_band & (triad['prop_extensive'] >= 0.05) & (triad['prop_extensive'] < 0.4),
        eligible & in_band & (triad['prop_extensive'] >= 0.4) & (triad['prop_extensive'] < 0.8),
        eligible & in_band & (triad['prop_extensive'] >= 0.8),
    ],
    choicelist=['crw_full', 'intensive', 'triad_i', 'triad_e', 'extensive'],
    default=np.where(eligible, 'none', triad['hcp_ws_assignment'])
)

The stand-level allocations determine the columns of \(\mathbf{X}\) (the proportions of reserve, intensive, and extensive), but we want to make sure that we don’t accidentally confound environmental conditions with the triad experiment when choosing the sensor locations. To do this, we add a DEM raster to get elevation, slope, and aspect. We also use the stand age as another control variable to help determine placement.

3 Terrain covariates

Elevation, slope, and aspect are derived from a 30 m DEM (USGS 3DEP, via py3dep), smoothed and downsampled to a 120 m grid, in python/get_course_dem.py. That script writes a 4-band raster (elevation, slope, aspect_x, aspect_y) to Data/esrf_alloc/dem_esrf_120_terrain.tif, which I load here.

Using the centroids of each 120 m grid cell in the landscape, we extract the geospatial data to a spatial points data frame. This provides a list of candidate locations at which to locate sensor nodes.

4 Creating the candidate site data

Code 
from shapely.geometry import Point

esrf_proj = esrf.to_crs(dem_120_terrain.rio.crs)
# simplified stand-level allocation, for stratifying site placement by
# stand allocation within a watershed treatment (see ALLOC_SIMPLE_MAP above)
esrf_proj['alloc_simple'] = esrf_proj['ops_allocation'].replace(ALLOC_SIMPLE_MAP)
# attach per-watershed treatment proportions so candidate_locs carries them too
esrf_proj = esrf_proj.merge(
    triad[['hcp_wtr_shd_id', 'prop_intensive', 'prop_extensive', 'prop_reserve', 'triad_trt2']],
    on='hcp_wtr_shd_id',
    how='left'
)
bio_proj = bio_sites.to_crs(dem_120_terrain.rio.crs)
roads_proj = roads.to_crs(dem_120_terrain.rio.crs)
eus_proj = eus.to_crs(dem_120_terrain.rio.crs)

# Build spatial points from the terrain raster's cell centers
xs = dem_120_terrain.x.values
ys = dem_120_terrain.y.values
elev_vals = elevation.values
slope_vals = slope.values
aspect_x_vals = aspect_x.values
aspect_y_vals = aspect_y.values
xx, yy = np.meshgrid(xs, ys)
x_ind, y_ind = np.meshgrid(
    range(len(xs)),
    range(len(ys))
)

nodata = dem_120_terrain.rio.nodata
mask = (elev_vals != nodata) if nodata is not None else np.ones(elev_vals.shape, dtype=bool)

candidate_locs = gpd.GeoDataFrame(
    {
        'elevation': elev_vals[mask],
        'slope': slope_vals[mask],
        'aspect_x': aspect_x_vals[mask],
        'aspect_y': aspect_y_vals[mask],
        'index_x': x_ind[mask],
        'index_y': y_ind[mask]
    },
    geometry=gpd.points_from_xy(xx[mask], yy[mask]),
    crs=dem_120_terrain.rio.crs
)

# Spatial join: attach triad polygon attributes to each point in the grid
candidate_locs = gpd.sjoin(
    candidate_locs,
    esrf_proj[[
        'geometry', 'age_2020', 'triad_trt2', 'ops_allocation',
        'alloc_simple', 'hcp_wtr_shd_id', 'prop_intensive', 'prop_extensive',
        'prop_reserve'
    ]],
    how='left',
    predicate='within'
)
# drop the 'index_right column'
candidate_locs.drop('index_right', axis=1, inplace=True)

# conduct a spatial join with the biodiversity sites
## first grab the columns we actually want
bio_proj_cols = ['station_id', 'geometry']
bio_proj_sa = gpd.sjoin(
    bio_proj[bio_proj_cols],
    eus_proj[['hcp_wtr_shd_id', 'geometry']],
    how = 'inner',
    predicate = 'within'
)
bio_proj_sa.drop(['index_right', 'hcp_wtr_shd_id'], axis = 1, inplace = True)

# now find the nearest candidate to each biodiv site within
# the study area
bio_div_join = gpd.sjoin_nearest(
    bio_proj_sa,
    candidate_locs.reset_index(names = "cell_id")[['cell_id', 'geometry']],
    how = 'left'
)
bio_div_join.drop(['index_right'], axis = 1, inplace = True)
bio_div_join.rename({'geometry': 'geometry_bio'}, axis = 1, inplace = True)

# now join these back to identify which cells contain the the biodiv sites
candidate_locs = bio_div_join.join(candidate_locs, on='cell_id', how="right")

# fill the nas in the station_id
candidate_locs['station_id'] = candidate_locs['station_id'].fillna('none')
# only keep the grid cell locations (i.e., "snap" the biodiv monitoring sites to the grid cell centers)
candidate_locs.drop(['geometry_bio'], axis = 1, inplace = True)
candidate_locs = candidate_locs.dropna()

# create filter mask
mask = np.array(np.repeat(1, candidate_locs.shape[0]), dtype = 'bool')
mask[candidate_locs['triad_trt2'].isna().values] = False
mask[
    (candidate_locs['triad_trt2'] == 'crw_partial')
    .values
] = False

# filter out the treatments we are not interested in
candidate_locs = candidate_locs[mask]

Next step is to compute, for each point, the distance to the nearest road based on the roads layer.

Code 
candidate_locs = candidate_locs.sjoin_nearest(
    roads_proj,
    'left',
    distance_col = "dist_to_road_m"
)
candidate_locs.drop('index_right', axis=1, inplace=True)

5 Saving data

I save all the derived data layers to a geopackage for use in the sensor placement analysis.

Code 
import os

if not os.path.isdir(here('Data/sensor_optim')):
    os.mkdir(here('Data/sensor_optim'))

# save eus_proj, since it is the same CRS as candidates
esrf.to_file(
    here('Data/sensor_optim/data_for_optim.gpkg'),
    driver = 'GPKG',
    layer = 'esrf_alloc'
)

eus.to_crs(esrf.crs).to_file(
    here('Data/sensor_optim/data_for_optim.gpkg'),
    driver='GPKG',
    layer='eus'
)

# add layer to sensor optim data file
# using same crs as eus
candidate_locs.to_crs(esrf.crs).to_file(
    here('Data/sensor_optim/data_for_optim.gpkg'),
    driver='GPKG',
    layer='candidate_locs'
)

# reprojected biodiversity sites, for use in result maps in the main report
bio_proj.to_crs(esrf.crs).to_file(
    here('Data/sensor_optim/data_for_optim.gpkg'),
    driver='GPKG',
    layer='bio_sites'
)
